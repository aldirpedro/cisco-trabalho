01

Explique de que forma os seguintes serviços trabalham em conjunto numa rede empresarial: DHCP, DNS, WEB, EMAIL.

▼

Numa rede empresarial moderna, estes quatro serviços formam uma cadeia interdependente que permite a comunicação e o acesso a recursos digitais de forma transparente para o utilizador.


  • 1º — DHCP (atribuição automática de endereços):
    Quando um computador, smartphone ou qualquer dispositivo se liga à rede, o primeiro passo é obter um endereço IP. O servidor DHCP responde a um broadcast do cliente e atribui automaticamente: endereço IP, máscara de sub-rede, gateway padrão e o endereço do servidor DNS. Sem esta etapa, o dispositivo não consegue comunicar com outros na rede.

  • 2º — DNS (resolução de nomes):
    Com o IP já configurado, quando o utilizador escreve um endereço como www.empresa.pt no browser, o sistema operativo consulta o servidor DNS (cujo IP foi fornecido pelo DHCP). O DNS traduz esse nome para o endereço IP real do servidor WEB. Se o DNS falhar, nenhum serviço identificado por nome estará acessível.

  • 3º — WEB (acesso a páginas e aplicações):
    Com o IP do servidor resolvido pelo DNS, o browser pode agora enviar um pedido HTTP/HTTPS ao servidor WEB. Este responde com o conteúdo solicitado (HTML, imagens, dados). Numa empresa, o servidor WEB pode alojar a intranet, o portal de recursos humanos, sistemas ERP ou qualquer aplicação interna.

  • 4º — EMAIL (comunicação assíncrona):
    O servidor de email também depende do DNS — quando envia uma mensagem para colaborador@parceiro.com, consulta os registos MX do domínio parceiro.com para saber qual servidor de email contactar. O DHCP garante que o cliente de email tenha conectividade, o DNS resolve os endereços dos servidores de mail, e o SMTP/IMAP/POP3 tratam do envio e receção.

Em resumo: o DHCP é o "ponto de entrada" na rede; o DNS é o "intérprete" que converte nomes em endereços; o WEB e o EMAIL são os "serviços de topo" que dependem dos dois anteriores para funcionar.

02

Indique uma situação prática em que FTP pode ser utilizado numa escola.

▼

O FTP (File Transfer Protocol) tem várias aplicações práticas num ambiente escolar:


  • Partilha de materiais didáticos:
    Um professor de informática pode fazer upload de apresentações, exercícios práticos, softwares e vídeos tutoriais para o servidor FTP da escola. Os alunos acedem ao servidor com as suas credenciais e fazem download dos ficheiros diretamente para os seus computadores — sem necessidade de pen drives ou emails volumosos.

  • Entrega de trabalhos dos alunos:
    Os alunos podem fazer upload dos seus projetos para uma pasta específica do servidor FTP (ex.: /entregas/turma-12A/). O professor acede remotamente e avalia os trabalhos sem deslocações físicas.

  • Publicação do site escolar:
    O webmaster da escola utiliza FTP para publicar e atualizar as páginas HTML do site oficial, fazendo upload dos ficheiros para o servidor WEB.

  • Backup centralizado:
    O servidor FTP serve de repositório central para backups de dados importantes — fichas de alunos, registos administrativos — com acesso controlado por utilizador e password.

Vantagem prática: o FTP permite transferências de ficheiros muito grandes (vídeos, pacotes de software) de forma eficiente, algo que seria impraticável por email. Com permissões bem definidas (leitura, escrita, exclusão por pasta), é possível implementar um sistema de partilha seguro e organizado.

03

O que aconteceria se o servidor DNS falhasse?

▼

A falha do servidor DNS teria consequências imediatas e graves para toda a rede, mesmo que os outros servidores (WEB, EMAIL, FTP) continuassem a funcionar normalmente:


  • Impossibilidade de aceder a sites por nome:
    Os utilizadores não conseguiriam abrir www.escola.pt no browser. A única alternativa seria escrever diretamente o endereço IP (ex.: 192.168.7.10), o que é impraticável para a maioria dos utilizadores e impossível se não souberem os IPs.

  • Email deixa de funcionar:
    O envio de emails falha porque o servidor de email não consegue resolver os registos MX dos domínios destinatários. As mensagens acumular-se-iam na fila de envio.

  • Serviços cloud e externos indisponíveis:
    Qualquer serviço que dependa de resolução de nomes (Microsoft 365, Google Workspace, atualizações automáticas) ficaria inacessível.

  • Impacto nos clientes DHCP:
    Se o servidor DNS falhar antes de um cliente receber as suas configurações DHCP, o campo "DNS Server" na configuração de rede ficará em branco ou apontará para um servidor inativo.

  • Soluções de mitigação:
    — Configurar um DNS secundário (servidor de redundância) como failover
    — Usar servidores DNS públicos como backup (ex.: 8.8.8.8 da Google)
    — Implementar cache DNS local nos routers para responder enquanto o servidor principal está em baixo
    — Monitorização ativa com alertas automáticos
04

Em que situação é recomendado usar IP estático em vez de DHCP?

▼

O IP estático (configurado manualmente, sempre o mesmo) é recomendado em situações onde o endereço IP de um dispositivo nunca pode mudar, pois outros dispositivos ou serviços dependem de encontrá-lo sempre no mesmo endereço:


  • Servidores (WEB, EMAIL, DNS, DHCP, FTP):
    É o caso mais crítico. Se o servidor DNS tiver um IP dinâmico e este mudar, todos os clientes que apontam para ele deixarão de ter resolução de nomes. O mesmo aplica-se a WEB e EMAIL — os clientes precisam de saber sempre onde encontrar esses servidores.

  • Impressoras de rede:
    Quando um utilizador configura uma impressora de rede, guarda o seu endereço IP. Se a impressora receber um IP diferente do DHCP após reiniciar, a impressão falha. Com IP estático, a impressora está sempre acessível.

  • Câmeras de vigilância e IoT:
    O software de gravação e monitorização acede às câmeras por IP. Um IP dinâmico tornaria o sistema de segurança instável.

  • Routers e switches geridos:
    Os equipamentos de rede precisam de IPs fixos para que os administradores consigam aceder à sua interface de gestão de forma consistente.

  • Servidores de jogos ou aplicações:
    Qualquer servidor ao qual os clientes se ligam diretamente pelo IP beneficia de endereço estático.

  • Alternativa elegante — Reserva DHCP:
    Em vez de configurar o IP manualmente no dispositivo, é possível configurar o servidor DHCP para atribuir sempre o mesmo IP a um dispositivo específico, com base no seu endereço MAC. Combina a gestão centralizada do DHCP com a previsibilidade do IP estático.

Regra prática: se um dispositivo presta serviço a outros, use IP estático (ou reserva DHCP). Se um dispositivo consome serviços, use DHCP.
